# 管道、UDP 等待与多核工作者：六栏信息图规格

这是交给图像生成工具的文字规格。**三张图片已生成并视觉审校**，保存为 `docs/illustrated/images/pipe-cooperation.png`、`udp-wait.png`、`parallel-workers.png`，具体来源与编辑记录见 [图片清单](../images-cooperation.json)。详细解释见 [逐函数教程](../COOPERATION_FUNCTIONS.md)。内容对照提交 `67efd0d008e0b58b31c89ad4ecfbab502416e087` 的当前实现。

## 统一画风与排版

参照用户提供的六栏教学信息图：白底、黑色衬线大标题、**三列两行，共六个圆角面板**，从左到右、从上到下标 `(a)` 到 `(f)`，横向约 3:2。不是六列挤在一行。蓝色表示输入、标签、Ready；绿色表示成功、有效数据；橙色表示等待、资源上限；红色表示必须守住的条件。使用队列格子、文件标签、引用箭头、CPU 方块和简短时间轴，避免装饰性芯片照片。

每栏优先画一幅小流程或状态变化，正文控制在三行短句。图中保留短函数名 `pipe`、`spawn`、`read`、`write`、`close`，长内核函数名放在本规格的“对应源码”列供 Markdown 查阅。各图副标题带“当前实现”。不要用“最快”“无锁”“零拷贝”“自动迁移”等结论。

## 1. `pipe-cooperation.png`

标题：**管道协作：标签可以复制，字节沿队列流动**。
副标题：**共享内核对象 · 4096B 缓冲 · 阻塞与唤醒 · 当前实现**。

| 栏 | 图面短文 | 必须画出的变化 | 对应源码 |
| --- | --- | --- | --- |
| (a) 三层关系 | 进程自己的 fd；共享读／写端对象；同一个字节队列。 | 左侧“父进程 fd3／fd4”，各自箭头指向读端／写端对象，两对象都指向同一 4096B 管道。不要画 fd3 本身就是缓冲区。 | `fd_pipe`、`attach` |
| (b) 创建与继承 | `spawn` 复制标签；对象引用数增加；用户内存仍私有。 | 父写 fd4 与子写 fd4 指向同一写端对象，`references: 1→2`。读端对象另画。旁注：共享文件对象还共享 offset。不要画复制了整份管道。 | `fd_inherit`、`fd_dup2` |
| (c) 小写入不拆开 | 一次 `write ≤4096B`；整块放得下才写；不足先等待。 | 空间 300B、记录 257B：整条绿色入队；空间 100B、记录 257B：橙色 Blocked，禁止画先写 100B。小注：更大写入可分段穿插。 | `pipe_write` |
| (d) 读取字节流 | `read` 可以只取一部分；释放空间；唤醒等待写者。 | 4096B 圆环标 head/count；父进程每次最多读 777B，拼回 257／4096B 记录。箭头“读取 → count 减少 → 写者 Ready”。不得画成每次 read 自动获得一整条消息。 | `pipe_read`、`cooperate`、`check_record` |
| (e) 等待不空转 | 持内核锁＋关本地中断；登记后切走；事件发生再 Ready。 | Running → 登记等待 → Blocked → 切换到其他线程；生产者写入或消费者腾空间 → Ready。红色连线圈住“检查／登记／阻塞”原子边界。小注：CLI 只管本核，跨核靠 BKL。 | `wait_on`、`wake` |
| (f) 关闭的两种结果 | 缓冲空＋最后写端消失：EOF；最后读端消失：EPIPE；最后引用释放对象。 | 两条分支：①仍有父写标签 → 子 close 后不 EOF；父也 close → 排空后 read=0。②所有读标签 close → 等待写者醒来，write=-7。不要把“关闭任意一个标签”画成直接 EOF。 | `fd_close`、`release`、`blocked_writer` |

底部记忆句：**复制的是标签，延长的是对象生命；EOF 要等最后一个写端。**

补充制图校验：`PipeState.readers/writers` 数的是仍存活的端点对象。`dup` 和 `spawn` 增加对象的 `references`，不直接增加这两个计数。图中用“最后一个写端”表达最终生命期，避免把计数画成每个进程各加一。

## 2. `udp-wait.png`

标题：**UDP 阻塞接收：睡下去之前，把唤醒路线接好**。
副标题：**PID 与代数校验 · 原始截止时间 · BSP 单队列 · 当前实现**。

| 栏 | 图面短文 | 必须画出的变化 | 对应源码 |
| --- | --- | --- | --- |
| (a) 找对收件箱 | 句柄＝槽号＋代数；同时检查拥有者 PID；4 个 socket × 每箱 4 包。 | “PID 7、handle”经校验指向 inbox；另一 PID 的相同数字被红叉拒绝；旧代数与新 socket 不匹配。最大 payload 1200B。 | `lookup_socket`、`network_udp_open` |
| (b) 只算一次期限 | 0：立即探测；1…60000ms：有限等待；MAX：无限等待。 | 时间轴：PIT now=100、25ms 向上取整 3 tick、deadline=103。被提前唤醒仍保留 103，不重新加 3。小注：100Hz，排队可能更晚运行。 | `timeout_ticks`、`network_udp_receive_wait` |
| (c) 空箱时登记 | BKL＋CLI；登记 thread 与 tid；切走之前保护不放开。 | 空 inbox → waiters 写入 `{thread, tid}` → Blocked → 保存旧栈／切换。红框标“登记与阻塞间不能漏唤醒”。不要画 AP 持锁执行 HLT。 | `network_udp_receive_wait` |
| (d) 真正的包到达 | Virtio RX → BSP worker；校验 Ethernet／IPv4／UDP；入箱后唤醒一个。 | 网卡 → CPU0 worker → 四格 inbox 一格变绿 → 接收者 Ready／目标核通知。AP 用户线程从 inbox 取包，不画 AP 的独立 RX ring。元数据 reserved=0。 | `network_poll`、`receive_frame`、`receive_udp`、`wake_udp_receivers` |
| (e) 醒来再检查 | Ready 不等于拿到包；重验 PID／代数／原始期限；复制前重验可写用户映射。 | Ready → 本核 Running → 分支“箱有包？”；旁边红框“输出映射仍有效？”；缓冲太小 → -2、包仍在箱内。画其他接收者先拿走包后重新等的回路，deadline 不变。 | `network_udp_receive_wait` |
| (f) 完整结束路径 | ≥0：有效包，0 是空包；-1：无包／超时；关闭与设备故障也唤醒。 | 三支：到包→长度；到期且无包→-1；等待中 close／owner 退出→全部唤醒→-4；设备不可用→-3。小注：初次传旧句柄是 -2；close 不发 TCP FIN。 | `network_udp_close`、`network_udp_close_owner`、`network_status` |

底部记忆句：**醒来只说明条件可能改变；身份、内存和最初期限都要再核对。**

补充制图校验：数据已经入箱时，接收路径先取数据，再检查是否超时。有限期限来自 BSP PIT，调度器内部另有计数起点，调用 helper 会把剩余时间换算过去。只画一条统一时间轴，不把四颗 CPU 的 tick 相加。`MAX` 在图中表示 `UINT32_MAX` 用户超时参数，内核无限 deadline 是 `UINT64_MAX`。

## 3. `parallel-workers.png`

标题：**多核协作：并行计算，把结果交给可验证的消息流**。
副标题：**最多 4 核 · 首次选择后固定绑定 · 内核 BKL 串行 · 当前实现**。

| 栏 | 图面短文 | 必须画出的变化 | 对应源码 |
| --- | --- | --- | --- |
| (a) 每个工作者有私有内存 | 父进程创建子进程；代码在各自地址空间运行；管道对象由内核共享。 | 父＋三个子进程，各画私有用户栈／堆；仅 fd 箭头汇到共享管道。不要画所有子进程共享同一用户堆。 | `cooperate`、`smp_test::main` |
| (b) 首次选核，之后不搬 | 首次调度选择负载较少 CPU；绑定后保持；12 个工作者分时使用最多 4 核。 | CPU0…3 四方块，12 工作者分配多张小卡；后续每卡保留颜色与 CPU。小注：没有迁移／work stealing；不画 12 核。 | `smp_test::worker`，调度细节见其它图 |
| (c) 计算并行，内核排队 | 用户计算可同时运行；syscall／IRQ 进入 BKL；阻塞后让出执行机会。 | 四条用户计算绿色泳道；中间只有一条“内核服务 BKL”橙色门；调用后返回各原 CPU。不可画内核网络／文件服务无锁并行。 | `bench_compute`、三个测试的 worker／receiver |
| (d) 抢占与绑定验证 | 12 工作者 × 6 轮；每轮 2000 万次整数计算；40B 进度记录。 | 每 worker 计算→私有 64KiB 数据检查→pipe→父验证完整结果／轮次／CPU 不变；标明计算循环不主动 yield。故障子进程另画为资源回收检查。 | `smp_test::worker`、`smp_test::main` |
| (e) 多写者记录验证 | 每 64 条做 50 万次计算；257／4096B 单次写；父按序拼接并验内容。 | 多个写者的完整记录依次入管道；父每次最多 777B read，按 32B 头＋长度重建。标“仅保证各 worker 自身顺序”，不同 worker 的交错顺序不固定。 | `coop_test::worker`、`check_record`、`cooperate` |
| (f) 计算＋真实 UDP | 先创建计算者，再放行网络子进程；BSP 收包，接收者可在 AP；检查包内容与计算退出码。 | parent 启动 receiver→创建 0…3 bench→gate 写 g→receiver 发／等 0、1、257、1200B echo；同时画计算泳道。小注：gate 只约束网络起点，不是所有线程的同时起跑屏障。 | `udp_mixed::main`、`receiver` |

底部记忆句：**用完整结果、记录顺序、CPU 身份与资源回收验证协作，不只看“跑完了”。**

补充制图校验：`user_ticks` 按用户 TCB 归属记账，也包含该线程在内核服务中的时间，不是纯 ring3 占用率。图内不填写未经正式测量的加速倍数；这些程序证明功能正确和执行覆盖，不直接证明优于 Linux。当前没有 TCP、用户共享内存接口或 futex；不要为它们画已连通的数据路径。

## 图块映射

逐函数正文用 `P(a)`…`P(f)` 对应 pipe 图，`U(a)`…`U(f)` 对应 UDP 图，`M(a)`…`M(f)` 对应多核图。读写网络字节序、校验和等小函数共同归入 `U(d)`；格式化辅助函数归入使用它们的测试图块。图只概括动作，逐函数正文承担输入、输出、步骤、原因与限制。
