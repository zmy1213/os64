# 文件系统、Shell和用户工具七张六栏图规格

对应[文件系统131项](../FILESYSTEM_FUNCTIONS.md)、[Shell87项](../SHELL_FUNCTIONS.md)、[其余用户程序80项](../USER_PROGRAM_FUNCTIONS.md)，共298项。白底、约16:9宽幅、三列两行，浅蓝／绿／橙／紫／粉／青，(a)–(f)短句加流程和状态图。使用内置imagegen直接生成，原始文件保留，准确prompt见prompts/，实际尺寸与审校见images-files.json。七张最终图已生成并通过视觉审校；全部实际尺寸1672×941，生成和修订状态以图清单为准。

## L：os64fs-layout.png

标题：OS64 文件怎样放在磁盘
副标题：512B块 · 名字找到inode · inode找到内容
(a) 磁盘布局：画横向五区域依次“superblock”“inode位图”“data位图”“inode表”“数据区”。小字“卷内扇区号”。
(b) 位图记占用：画8格示例位图，0=空闲、1=占用，inode0号保留为1，箭头关联一个inode槽和数据块。短句“块号从数据区起算”。
(c) 目录与inode：画64B目录项“名字 → inode号”，指向inode卡“类型 / 大小 / 块映射”。短句“目录项64B · 名字最多56B”。inode号4B，其余type/name_length/flags共4B；目录项不是数据块指针。
(d) 两层内容索引：inode画8个直接箭头指向8块，另一个箭头到“128项间接表”再到数据块。短句“内容最多69632B”“间接表另占1块”。不要画双重或三重间接。
(e) 读取一段：偏移500B读76B；块0末尾12B加块1开头64B。流程“文件偏移 → 块索引 → 设备扇区 → 字节片段”。图形非等比例。短句“不能越过EOF”。文件偏移不同于块号与扇区号。
(f) 挂载先校验：画“布局 → 位图与引用 → 目录可达性 → 挂载”，旁边失败分支“损坏则拒绝”。短句“根目录 · 深度最多16”。不要画自动修复。


## T：filesystem-transactions.png

标题：OS64 修改文件的失败保护
副标题：内存暂存 · 校验后提交 · 同步错误可回滚
(a) 先找目标：画“路径 → 父目录 → 名字”，分支“已有 / 新建”。短句“先验证操作”。
(b) 保存内存状态：画内存卡包含“superblock / 位图 / inode缓存”，复制到“旧状态”。短句“不是磁盘日志”。
(c) 暂存扇区：画两列“旧内容 / 新内容”，每行同一扇区号；操作写入新列。短句“最多256个不同扇区”“真实磁盘尚未写”。
(d) 完整校验：画“修改完成 → 分配与目录一致性检查”，失败到“恢复旧内存状态 → 返回失败”，不画自动重试。短句“校验失败不提交”。
(e) 写盘与回滚：两个阶段框“提交：写新扇区+flush”和“恢复：逆序旧扇区+flush”。提交阶段成功到成功，任一步失败到恢复阶段；恢复成功返回原失败，恢复失败停止挂载。小字“失败的写入尝试也需恢复”。不画直接跳到恢复flush的旁路。
(f) 实际边界：画RAM暂存遇到断电消失，磁盘上写到一半有问号。大短句“无持久化日志”“无断电恢复事务”。小字“sync是请求设备flush”。不要暗示电源故障也原子成功，不画原子rename。


## V：vfs-paths.png

标题：OS64 名字怎样变成文件内容
副标题：VFS统一接口 · OS64FS根卷 · 打开后用偏移
(a) 接口分层：画“用户API → VFS → file / directory → OS64FS → 块设备”。短句“当前只有一个根卷”。不画多挂载、多文件系统插件。
(b) 路径走目录：从根inode画/a/b，再路径“/a/./b/..”回到a。短句“重复/可跳过”“..到根就停”。小字“cwd在系统调用层解析”。底层相对路径也从根，不要画VFS自己存cwd。
(c) 打开文件：画“路径查找 → inode号 → FileHandle”，卡上“文件引用 / offset=0”。短句“FD共享对象见协作图”。不要把每个FD都画成独立文件offset。

(e) 读取与刷新：画“按inode号刷新 → 检查EOF → 限定长度 → 读内容 → 推进offset”。短句“其它FD可改大小”。

## Q：shell-parser.png

## X：shell-pipeline.png

标题：OS64 Shell 怎样接好管道
副标题：共享打开对象 · 关闭多余端点 · 等待并回收
(a) 先检查程序：画“命令名 → /bin路径 → 普通文件检查”。短句“先检查全部路径”“ELF校验在spawn”。仅存在／普通文件，不查mode执行权限，不暗示此步已证明ELF有效。
(b) 保存父进程流：画Shell的0/1/2三个格，dup箭头指向“保存引用”。短句“指向同一打开对象”。不是拷贝文件内容。
(c) 建管道与重定向：画stage1 stdout=写端 → 4096B管道 → stage2 stdin=读端，stage2 stdout指向文件。短句“显式重定向覆盖管道连接”。
(d) 启动子进程：画“配置0/1/2 → spawn → 继承引用”，两子各只保留所需标准流，旁边“关掉额外FD”。不画fork复制地址空间。
(e) 父恢复并关闭：画“恢复0/1/2 → 关闭保存FD与管道FD”，再画“最后写端对象释放 → 读尽后EOF”。不要把父关闭一份引用就立刻EOF。
(f) 等待与失败：左画“前台wait所有 → 回收 → 末阶段状态”，右画“后台登记 → jobs / wait”。短句“最多4阶段、4后台槽”“准备失败不撤销已截断文件”。不画pipefail、完整终端作业控制。

## E：user-editor.png

标题：OS64 编辑器：先改内存，再确认保存
副标题：行编辑 · 完整加载 · 失败保留编辑
(a) 完整加载：画文件→512B分块→Buffer直到EOF。短句“文档最多32768B”“超限或NUL拒绝”“不截短保存”。缺文件箭头“空文档，save才创建”。
(b) 用户输入行：画stdin逐字符→命令Buffer，回显与退格箭头。短句“命令最多512B”“超长吞到回车，整行丢弃”。
(c) 行号到偏移：画两行文本与换行符，行号1/2指向字节起点。短句“行号从1”“无尾换行仍有最后一行”。
(d) 内存修改：画“检查行号与容量 → reserve → memmove → insert/delete”，Buffer角标“dirty”。短句“失败前不改正文”。别画多步失败后无条件成功。
(e) 保存确认：画“replace_file完整正文 → sync → dirty=false”。失败分支“编辑仍在内存”。短句“不是先TRUNC再write”“无断电恢复日志”。
(f) 离开与回收：画dirty分支“quit拒绝未保存”回编辑循环，save成功后quit和quit!放弃才接释放两个Buffer。短句“quit不自动保存”“没有undo”。


## 审校重点

L：内容69632B不含间接索引块；目录项64B、名字56B；数据块号和扇区号区分。T：最多256个不同扇区，旧新均留内存，commit失败的尝试也恢复；内存回滚不能跨断电。V：当前仅单根OS64FS卷，cwd解析在系统调用层；file_read按inode刷新再推进offset，目录游标不稳定快照。Q：交互255B和解析器512B分开，词63B含外加NUL，延迟变量不再分词。X：端点是共享对象，EOF依赖最后写端对象释放；预查只是普通文件类型，重定向截断不是完整pipeline事务。U：多核仅用户计算并行，BKL串行，UDP0B成功但无TCP。E：load读全再决定，命令整行吞掉，dirty只有保存确认才清，quit不自动保存。所有编辑修正仍使用imagegen，不做程序缩放、重绘、文字覆盖。
