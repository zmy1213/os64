# OS64 逐函数配图教程

这套讲义面向从零学习操作系统的读者：先看一张图理解“谁把什么交给谁”，再按函数名读具体输入、执行步骤、结果、错误边界和代价。**29 张机制图配合 1020 个 C++ 定义的逐函数解释**，每个函数都对应具体图块；共同参与一个流程的函数共享同一张图。所有图片都通过**内置 imagegen 直接生成**；有误的文字和箭头也用 imagegen 编辑，没有用 Python、SVG 或绘图库画图。配色与六栏版式参考用户提供的教学信息图，内容来自本仓库真实实现。

## 一张图应该怎样读

每张图采用六栏机制图。先看标题与副标题明确范围，读 (a) 的对象或输入，沿箭头追 (b)–(e) 的状态变化，最后读 (f) 的规则或边界。编号表示该栏内部的步骤；整张图的六栏不一定都是需要依次执行的六条指令。

例如 [就绪队列图](images/ready-queue.png) 不是“遇见本核线程立刻停止扫描”。当前代码选中本核候选后，继续处理原队列余下条目，保持其他CPU的FIFO顺序。图中 [A1,B0,C1] 给CPU0取出B0后剩下 [A1,C1]；如果画成 [C1,A1]，就把算法画错了。图下解释还计入反查线程槽的开销，不能只看简短图示便宣称 O(Q)。

函数很短时，例如一个寄存器读写或用户 syscall wrapper，图块讲它在整体流程的位置，表行解释具体输入与副作用；复杂函数另写状态机、失败回滚与实例。这样小函数也能查到，同时避免在一张图里塞入几十个长名字。

## 三个必须区分的概念

**并发与并行。** 一颗CPU交替运行多个进程叫并发；不同CPU同时执行用户计算才是本教程中的多核并行。图里有四条用户轨道，不表示四份内核服务也并行；当前共享内核状态由CPU所有的大内核锁保护。

**Ready与拿到结果。** wake 把等待者变得可以排队，并不保证立刻运行或事件仍在。睡醒后要重验管道状态、UDP句柄代数/PID、原截止期及用户输出映射。图的箭头应表达状态变化，不把唤醒画成“必然拿到包”。

**功能通过与速度最好。** 校验值正确、每颗核参与工作、退出资源回到原值，证明算法与协作能够运行。性能还要固定总工作量、重复采样与相同环境。新增归约的 [功能记录](validation/README.md) 包含原始结果；正式同QEMU Linux对照在 [既有多核性能报告](../measurements/smp/REPORT.md)，二者没有混成一套性能结论。

## 覆盖范围与源码绑定

[函数库存](FUNCTION_INVENTORY.json) 由 Clang 的语法树提取 `kernel/`、`user/` 内 `.cpp/.hpp` 的显式 C++ 定义：当前 **113 个源码文件、1020 个定义**，排除只声明未定义的函数、编译器隐式生成成员和重复包含的头文件定义。汇编入口在索引另列，不计入这个数字；构建/测试脚本中的宿主函数也不属于这份运行时库存。

每项包含路径、行号、签名和函数源码SHA256。[覆盖清单](FUNCTION_COVERAGE.json) 对应讲义与图块，可检查遗漏。原有内核函数实现与原测试讲义绑定提交 `67efd0d008e0b58b31c89ad4ecfbab502416e087`；本次仅纠正日志/性能头文件仍写“单核”的旧注释。新增 parallel_reduce 来自本次工作树，其源文件与被测ELF哈希见 [验证记录](validation/README.md)。库存里的提交号是抽取时的基线，新增项由源码哈希和工作树记录识别，不冒充已存在于旧提交。

宿主装有 Clang 时，可以在仓库根目录重新扫描：

```sh
python3 scripts/document-functions.py
python3 scripts/document-function-coverage.py
```

第一条只更新函数库存；第二条检查源码哈希和逐函数讲义对应关系，加 `--write` 才刷新索引与覆盖清单。它们不会生成图片或自动改写函数讲解。源码发生变化以后，要同时检查文字、图块、索引和实测记录；不能仅更新图片标题。

## 图片、提示词与审校记录

最终PNG都放在 [images/](images/)，原始内置生成文件保留在工具默认输出目录。每份精确提示词放在 [prompts/](prompts/)，源码核对后的图面规格放在 [specs/](specs/)。[统一图片清单](IMAGE_MANIFEST.json) 记录真实尺寸、最终哈希、原始路径、初稿及编辑提示词和审校项目。

审校同时检查排版与技术含义：文字能读、箭头方向明确、单位和数字一致、失败分支存在、没有把未来的迁移/无锁/共享内存/TCP等能力画成现有功能。图片支持机制直觉；要复制命令、函数名或错误码时，以紧随图的Markdown文本为准。

硬件原理可对照 [Intel 官方体系结构手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)。这个手册是CPU机制的参考，不能替代检查OS64目前实际实现的范围。
