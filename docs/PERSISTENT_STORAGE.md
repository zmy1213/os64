# 持久化数据卷

启动镜像仍通过软盘启动。内核只探测 IDE primary master 的 ATA 数据盘，
不会扫描其他磁盘，也不会自动格式化。该盘从 LBA 0 开始存放 OS64FS v3，
镜像可直接使用构建生成的独立数据卷。缺少设备或挂载校验失败时使用启动卷
的 RAM 副本；这个回退副本的改动不会在重启后保留。

storage/ata_pio.cpp 提供 IDENTIFY、单扇区 PIO 读写和 FLUSH CACHE。
每次状态等待最多轮询 1,000,000 次；缺失设备、ATAPI、非 LBA 设备、
大于 512 字节的逻辑扇区和设备错误会返回失败。接口当前使用 LBA28，
最多暴露 268,435,456 个 512 字节扇区。实际文件系统的容量限制更小。

BlockDevice 统一 RAM 和 ATA 的读写入口，并增加可选 flush 回调。
内存卷不需要介质刷新。OS64FS 成功返回一次变更之前，完成元数据写回和
设备 flush，因此正常关闭 QEMU、重启并重新挂载后可以读到这些变更。

OS64FS v3 的明确限制：

- 固定 512 字节扇区和数据块，最多 128 个 inode 槽位，0 号保留。
- 数据位图缓存最多 4096 字节，最多表示 32768 个数据块。
- 每文件 8 个直接块和 128 个单级间接槽位，最多 69632 字节。
- 文件名最多 56 字节；路径最多 16 层，包含根目录这一层。
- 同一 inode 只能有一个目录引用；没有硬链接或符号链接。
- 只删除空目录。

一次创建、写入、追加或删除使用有界内存事务：在堆上保存至多 256 个修改
扇区的原始内容和新内容，以及文件系统缓存快照。准备阶段的读会看到暂存
内容，写不会到达设备。只有整次操作和分配/目录一致性校验成功后才提交。
空间不足、非法参数、过大文件、读取失败都丢弃暂存内容；提交写失败时尝试
恢复所有已尝试扇区（包括可能部分写入的失败扇区），然后 flush。硬件持续
失败导致无法回滚时，文件系统取消挂载，避免继续覆盖仍被引用的数据块。
这些操作要求内核堆已初始化；现有启动顺序满足这一要求。

这不是磁盘日志。提交过程中突然断电或强制终止可能留下不一致的卷；
目前重新挂载会拒绝检测到的坏卷，没有自动修复或日志重放。正常成功返回
后的持久化和可恢复的 I/O/空间不足失败处理已实现，断电原子性属于后续工作。

文件句柄的 read、stat 和 seek 每次按 inode 号刷新元数据，能看到其他描述符
完成的覆盖或追加。系统调用层应拒绝删除仍被打开的 inode，以免句柄在 inode
复用后指向另一文件。

设备错误导致取消挂载后，已有文件和目录句柄仍能关闭；进程仍可退出，
写 stdout/stderr、查询 PID 或等待子进程。文件系统失效不会把这些独立的
进程和控制台操作一并禁用。

## 宿主回归测试

在仓库根目录执行：

    make test-storage-host

覆盖重新挂载、空间和 inode 耗尽、间接块反复回收、已打开句柄刷新、
部分扇区 I/O 故障回滚、flush 失败、超大参数和恶意布局溢出。

ATA 字段和命令依据厂商的
[ATA 设备手册](https://www.seagate.com/www-content/product-content/momentus-fam/momentus-thin/en-us/docs/100713732k.pdf)；
QEMU 启动时需将数据镜像接到 if=ide,index=0，启动镜像保持 if=floppy,index=0。
