# 修正时钟域后的最终网络回归

这份 2026-10-03（Asia/Shanghai）记录对应最终普通内核 **285,776 B**，SHA256 `24046ac50ff0829b2b7d99ffbf5465081298d579e41d60154a7ba43b10a16ba3`。它补上父目录旧实验未覆盖的“AP 上有限超时的上界”，旧 JSON 和构建清单仍保持原样。

三组顺序运行，均使用同一个启动盘和用户工具：QEMU 10.2.0、qemu64、TCG、128 MiB；2/4 vCPU 启用多线程 TCG。每组使用独立临时数据盘、legacy virtio-net 单队列 IRQ11。每组包括 ARP/ICMP、128 次顺序回显、256 包突发、UDP API 权限和坏参数、有限等待、未缓存 ARP 超时、0/3 计算者的阻塞收发，以及退出关闭 socket。

| vCPU | 25ms 等待的 CPU | 实际等待 PIT tick | 突发接收 | 无计算/三个计算者的 UDP 往返 | 计算校验和 |
|---|---:|---:|---|---|---:|
| 1 | 0 | 3 | 256/256 | 64/64、64/64 | 283 |
| 2 | 1（AP） | 3 | 256/256 | 64/64、64/64 | 283 |
| 4 | 1（AP） | 3 | 256/256 | 64/64、64/64 | 283 |

全局 PIT 为 100Hz，25ms 向上取整为 3tick；脚本要求空闲测试在 **3–6tick** 内返回 `-1`。这里证明当前测试环境中定时唤醒能按上界返回，不能据此承诺系统过载或真实硬件上的硬实时期限。2/4 核的未缓存 ARP 等待也在 AP 上执行：等待者进入调度器，释放内核 gate，让 BSP 继续更新时间与处理网络。

每个混合负载的三个计算者各运行一亿次确定运算，逐个核对完整计算结果。四核混合组所有四颗 CPU 的用户归属 tick 均有增量。接收者在 AP1，RX ring 仍由 BSP 的网络工作线程消费。所有组 UDP dropped、设备错误和 tx_busy 为零；用户物理页回收检查与原有数据盘摘要检查通过。

这是每配置一次的功能验证，没有统计重复采样，不能用突发吞吐或混合负载耗时给系统排名。`user_ticks` 是本核用户线程处于 Running 时的定时器归属计数，也包含该线程的内核服务时段；它不是纯用户态耗时或 CPU 利用率。

- [1cpu.json](1cpu.json)、[2cpu.json](2cpu.json)、[4cpu.json](4cpu.json)：原样复制的脚本输出，含环境、完整用户校验字段、CPU 证据、宿主耗时和网络统计。
- `1cpu-test.log`、`2cpu-test.log`、`4cpu-test.log`：完整回归输出。
- [build-manifest.json](build-manifest.json)：固定同一内核与全部用户工具摘要。
- [SHA256SUMS](SHA256SUMS)：归档文件摘要。
